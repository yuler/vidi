# 视频封面（自动抽帧）设计

日期：2026-08-16
状态：已确认

## 目标

给 Vidi 的视频加上真实封面：首页课程卡片、「继续观看」区、课程页每集列表都用 ffmpeg 从视频抽帧生成的封面，替代现有的纯 Play / Music 图标。音频（mp3/m4a）无画面，继续用图标兜底。

## 决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 封面来源 | 自动从视频抽帧 | 本机已有 ffmpeg，全自动，无需手工操作 |
| 封面范围 | 首页课程卡片 + 继续观看 + 课程页每集 | 体验完整 |
| 音频处理 | 不生成封面，用音符图标 | 没有画面，假封面无意义 |
| 生成时机 | 按需懒生成，落盘缓存 | 不阻塞扫描/列表，避免上百集预生成耗时长 |

## 架构

### 新增 API：`GET /api/cover/[...path]`

路径结构与 `/api/stream/[...path]` 相同（`rootIndex/courseDir/relPath`），复用索引查找。

处理流程：

1. 解析路径 → 在索引中查视频；查不到返回 404
2. 音频类型 → 返回 404（前端用图标兜底）
3. 计算封面缓存路径：`data/covers/<hash(video.path + mtime)>.jpg`
   - 命中且文件存在 → 直接以图片响应返回
   - 未命中 → 走抽帧流程
4. 抽帧成功 → 落盘 → 以图片响应返回

### 抽帧（ffmpeg）

- 用 `ffprobe` 读视频时长，取 **10% 位置**的帧（避开片头黑屏）
- `-vf scale=640:-2` 缩放到 640 宽，JPEG 质量适中，控制体积（封面只需列表缩略图清晰度）
- 文件名含视频 mtime，源文件变更后自动重新抽帧
- ffmpeg 路径解析：优先 PATH 上的 `ffmpeg`，找不到则回退 `/opt/homebrew/bin/ffmpeg`、`/usr/local/bin/ffmpeg`（launchd 环境 PATH 可能不完整）

### 并发与失败处理

- 进程内 `Map<string, Promise>` 记录 in-flight 抽帧，同一视频并发请求只抽一次
- 抽帧失败（超时 / ffmpeg 报错 / 文件损坏）→ 记入失败集合，返回 404；前端 `<img>` onerror 回退到图标
- 失败集合仅内存保留（重启后允许重试），不写盘

### 前端：新增 `VideoCover.vue` 组件

- 入参 `course` + `video`
- 渲染 `<img :src="coverUrl">`，`loading="lazy"`
- 音频类型 / 图片加载失败 / 404 → 回退到现有的 Play / Music 图标样式（`object-cover` 的 16:9 占位块）
- coverUrl 拼接：`/api/cover/{course.rootIndex}/{course.dir}/{video.path}`（各段 encodeURIComponent）

### 页面接入

| 页面 | 改动 |
|---|---|
| 首页课程卡片 | 用该课程第一个视频的封面作课程缩略图（16:9），无视频则保持纯文字卡片 |
| 首页「继续观看」 | 每张用对应视频封面替换 Play 图标，进度条保留 |
| 课程页每集列表 | 左侧缩略槽位换成封面，Play/Check/Music 状态标记叠加在封面上 |

## 数据流

1. 浏览列表 → 前端渲染 `VideoCover` → 浏览器请求 `/api/cover/...`
2. 服务端首次未命中 → 懒抽帧 → 落盘 `data/covers/` → 响应图片
3. 后续请求 → 直接读缓存文件返回（几乎零成本）
4. 源视频变更 → mtime 变化 → 文件名不同 → 自动重新抽帧

## 存储

- 封面目录 `data/covers/`，已被 gitignore 的 `data/` 覆盖
- 单文件即缓存单元，无需额外索引；文件名内嵌 mtime 保证失效

## 错误处理

- 磁盘未挂载 / 视频不存在 → 404，前端图标兜底
- ffmpeg 不可用 → 全部 404，UI 与现状一致，功能自动降级
- 损坏视频 / 抽帧超时 → 404 + 内存失败标记，不阻塞列表

## 部署

- 纯新增文件 + 少量修改，不涉及配置
- launchd 环境需保证能解析 ffmpeg 路径（已做绝对路径回退）
